# csv2vcf — แปลงรายชื่อผู้ติดต่อจากไฟล์ CSV เป็นไฟล์ vCard (.vcf)

แปลงไฟล์รายชื่อ `.csv` เป็นไฟล์ `.vcf` (vCard 3.0) เพื่อนำเข้าโทรศัพท์ Android, iPhone,
Google Contacts หรือ Outlook ใช้ได้ 3 แบบ:

1. **เว็บไซต์บน GitHub Pages** เปิดใช้ได้ทันทีโดยไม่ต้องติดตั้งอะไร แปลงในเบราว์เซอร์ทั้งหมด
2. **เว็บไซต์ที่รันเอง** (`webapp.py`)
3. **คำสั่งในเทอร์มินัล** (`csv2vcf.py`)

แบบที่ 2 และ 3 เขียนด้วย Python ใช้แค่ไลบรารีมาตรฐาน ต้องใช้ Python รุ่น 3.8 ขึ้นไป
คำสั่งทั้งหมดในเอกสารนี้ให้รันในโฟลเดอร์ `csv2vcf/` (ยกเว้นที่ระบุไว้)

## ใช้งานผ่าน GitHub Pages

เปิด <https://envburiramclub.github.io/claude-code/csv2vcf/> แล้วเลือกไฟล์ CSV กด **แปลงไฟล์** และ **ดาวน์โหลดไฟล์ .vcf**

- **ไฟล์ไม่ถูกส่งขึ้นอินเทอร์เน็ต:** แปลงด้วย JavaScript ในเบราว์เซอร์ทั้งหมด
  หน้าเว็บตั้ง Content-Security-Policy ห้ามเชื่อมต่อเครือข่าย (`connect-src 'none'`)
  จึงส่งข้อมูลออกไปที่ไหนไม่ได้แม้แต่เซิร์ฟเวอร์ของ GitHub
- **หน้าเว็บไม่ค้าง:** แปลงใน Web Worker รองรับไฟล์ถึง 50 MB
- **เปิดจากเครื่องได้:** ดับเบิลคลิก `csv2vcf/index.html` ได้โดยไม่ต้องมีอินเทอร์เน็ต

**การเผยแพร่:** GitHub Actions (`.github/workflows/static.yml`) เผยแพร่ทั้ง repo ขึ้น GitHub Pages
ทุกครั้งที่ push ขึ้น `main` (Settings → Pages → Source: **GitHub Actions**) ระบบนี้อยู่ในโฟลเดอร์ `csv2vcf/`
จึงเปิดได้ที่ `/claude-code/csv2vcf/` และมีลิงก์กลับหน้าหลักของ repo (`/claude-code/`) ที่รวมทุกระบบ
ดูสถานะการเผยแพร่ได้ที่แท็บ **Actions** ของ repo

**ทดสอบในเครื่องแบบเดียวกับ GitHub Pages:** รัน `python3 -m http.server 8000` ที่โฟลเดอร์บนสุดของ repo
แล้วเปิด <http://127.0.0.1:8000/csv2vcf/>

`web/index.html` (หน้าของ `webapp.py`) ถูกเผยแพร่ขึ้น GitHub Pages ไปด้วย แต่ใช้งานที่นั่นไม่ได้เพราะไม่มีเซิร์ฟเวอร์แปลงไฟล์
หน้านั้นจึงปิดการเลือกไฟล์ ไม่ส่งไฟล์ไปไหน และมีลิงก์พาไปเวอร์ชันที่แปลงในเบราว์เซอร์แทน

**ไฟล์ของหน้าเว็บ GitHub Pages (อยู่ในโฟลเดอร์ `csv2vcf/`):**

| ไฟล์ | หน้าที่ |
| --- | --- |
| `index.html`, `style.css`, `app.js` | หน้าเว็บ (`style.css` ต้องเหมือน `web/style.css` ทุกไบต์) |
| `worker.js` | แปลงไฟล์ใน Web Worker |
| `csv2vcf.js` | ตัวแปลงที่ port มาจาก `csv2vcf.py` ให้ได้ผลเหมือนกันทุกไบต์ |
| `csv2vcf-data.js` | ตารางข้อมูลที่สร้างจาก Python ด้วย `python3 tools/build_js_data.py` ห้ามแก้ด้วยมือ |

`tests/test_static_site.py` รันไฟล์ชุดเดียวกันผ่านทั้ง Python และ JavaScript แล้วเทียบผลทุกไบต์
(ต้องมี Node.js ถ้าไม่มีจะข้ามเทสต์นี้)

## ใช้งานผ่านเว็บไซต์ที่รันเอง

```bash
python3 webapp.py
```

แล้วเปิดเบราว์เซอร์ไปที่ <http://127.0.0.1:8000> เลือกหรือลากไฟล์ CSV มาวาง กด **แปลงไฟล์**
ดูตัวอย่างรายชื่อ แล้วกด **ดาวน์โหลดไฟล์ .vcf** หน้าเว็บเป็นภาษาไทยและใช้บนมือถือได้

| ตัวเลือก | ความหมาย |
| --- | --- |
| `--host` | ที่อยู่ที่รอรับการเชื่อมต่อ (ค่าเริ่มต้น `127.0.0.1` คือเปิดได้เฉพาะเครื่องนี้ ใช้ `0.0.0.0` ให้เครื่องอื่นในเครือข่ายเปิดได้) |
| `--port` | พอร์ต (ค่าเริ่มต้น 8000) |
| `--max-size` | ขนาดไฟล์ที่อัปโหลดได้สูงสุด หน่วยเป็นเมกะไบต์ (ค่าเริ่มต้น 10) |
| `--workers` | จำนวนไฟล์ที่แปลงพร้อมกันได้ (ค่าเริ่มต้น 2) |

ไฟล์ที่อัปโหลดถูกประมวลผลในหน่วยความจำและไม่ถูกบันทึกลงดิสก์ ผลลัพธ์ถูกส่งกลับพร้อมคำสั่งห้ามเก็บ cache

**เปิดให้คนอื่นใช้ผ่านอินเทอร์เน็ต:** ให้รันบนเครื่องเซิร์ฟเวอร์ แล้ววางไว้หลัง reverse proxy ที่ทำ HTTPS
เช่น Caddy หรือ nginx (รายชื่อเป็นข้อมูลส่วนบุคคล ห้ามส่งผ่าน HTTP ธรรมดา) proxy ยังช่วยจำกัดจำนวนคำขอต่อผู้ใช้
และรับมือ client ที่เชื่อมต่อช้าได้ดีกว่า ตัวอย่างการตั้งค่า Caddy:

```
contacts.example.com {
    reverse_proxy 127.0.0.1:8000
}
```

ถ้าต้องการใช้ WSGI server อื่น (เช่น waitress หรือ gunicorn) ให้ชี้ไปที่ `webapp:application`
และตั้งค่าผ่าน environment variable `CSV2VCF_MAX_MB` กับ `CSV2VCF_WORKERS`
(การจำกัดเวลาการเชื่อมต่อของ `webapp.py` จะไม่ทำงาน ให้ตั้ง timeout ของ server นั้นแทน)

## ใช้งานผ่านคำสั่งในเทอร์มินัล

```bash
python3 csv2vcf.py contacts.csv                      # ได้ไฟล์ contacts.vcf
python3 csv2vcf.py contacts.csv -o phone.vcf         # ระบุชื่อไฟล์ผลลัพธ์เอง
python3 csv2vcf.py contacts.csv --country-code 66    # 081-234-5678 -> +66 81-234-5678
python3 csv2vcf.py contacts.csv -o - > out.vcf       # ส่งผลลัพธ์ออกทางเอาต์พุตมาตรฐาน
```

ถ้าไฟล์ CSV เสียกลางไฟล์ โปรแกรมจะแจ้งข้อผิดพลาดและไม่ส่งผลลัพธ์ออกมาเลย จะไม่มีไฟล์ที่มีรายชื่อแค่บางส่วน

ลองกับไฟล์ตัวอย่าง: `python3 csv2vcf.py example.csv -o -`

| ตัวเลือก | ความหมาย |
| --- | --- |
| `-o, --output` | ไฟล์ผลลัพธ์ (ค่าเริ่มต้น: ชื่อเดียวกับไฟล์ CSV แต่นามสกุลเป็น `.vcf` ส่วน `-` คือส่งออกทางเอาต์พุตมาตรฐาน) |
| `-e, --encoding` | การเข้ารหัสอักขระของไฟล์ CSV (ค่าเริ่มต้น `auto`: ดูจากเครื่องหมาย BOM ของ UTF-8/UTF-16 ก่อน แล้วลอง UTF-8 และภาษาไทยของ Windows `cp874` ตามลำดับ) |
| `-d, --delimiter` | ตัวคั่นคอลัมน์ (`,` `;` `tab` `\|`) ค่าเริ่มต้นคือตรวจหาให้เอง และรองรับบรรทัด `sep=;` ที่ Excel ใส่ไว้ |
| `--country-code` | แปลงเบอร์ที่ขึ้นต้นด้วย `0` เป็นรูปแบบสากล โดยใส่รหัสประเทศ เช่น `66` |
| `--date-order` | ลำดับวันที่ของวันเกิดแบบ `xx/xx/yyyy`: `dmy` คือ วัน/เดือน/ปี (ค่าเริ่มต้น) หรือ `mdy` คือ เดือน/วัน/ปี |
| `--max-size` | ขนาดไฟล์ CSV สูงสุด หน่วยเป็นเมกะไบต์ (ค่าเริ่มต้น 50) |
| `-f, --force` | เขียนทับไฟล์ผลลัพธ์ที่มีอยู่แล้ว |
| `-q, --quiet` | ไม่แสดงคำเตือนรายแถว |

## คอลัมน์ที่รองรับ

แถวแรกของไฟล์ต้องเป็นหัวตาราง ชื่อคอลัมน์ภาษาอังกฤษจะพิมพ์ตัวเล็กหรือตัวใหญ่ก็ได้
และใช้ไฟล์ที่ส่งออกจาก **Google Contacts** (`Phone 1 - Type`, `E-mail 1 - Value`,
`Address 1 - City`, …) และ **Outlook** (`Mobile Phone`, `Business Fax`, `E-mail 2 Address`,
`Home Street`, …) ได้ทันทีโดยไม่ต้องแก้ไข

| ข้อมูล | ตัวอย่างชื่อคอลัมน์ |
| --- | --- |
| ชื่อเต็ม | `Name`, `Full Name`, `ชื่อ-นามสกุล`, `ชื่อเต็ม` |
| ชื่อ / นามสกุล / ชื่อกลาง | `First Name`, `Last Name`, `Middle Name`, `ชื่อ`, `นามสกุล` |
| คำนำหน้า / ชื่อเล่น | `Prefix`, `Nickname`, `คำนำหน้า`, `ชื่อเล่น` |
| บริษัท / ตำแหน่ง / แผนก | `Company`, `Job Title`, `Department`, `บริษัท`, `ตำแหน่ง`, `แผนก` |
| เบอร์โทร | `Phone`, `Mobile`, `Home Phone`, `Work Phone`, `Fax`, `เบอร์โทร`, `มือถือ`, `เบอร์บ้าน`, `เบอร์ที่ทำงาน` |
| อีเมล | `Email`, `E-mail Address`, `Work Email`, `อีเมล` |
| ที่อยู่ | `Address`, `Street`, `City`, `State`, `Postal Code`, `Country`, `ที่อยู่`, `ตำบล/แขวง`, `อำเภอ/เขต`, `จังหวัด`, `รหัสไปรษณีย์` |
| เว็บไซต์ | `Website`, `URL`, `เว็บไซต์` |
| วันเกิด | `Birthday`, `วันเกิด` (รูปแบบ `YYYY-MM-DD` หรือ `DD/MM/YYYY` ถ้าเป็นปี พ.ศ. จะแปลงเป็น ค.ศ. ให้เอง) |
| หมายเหตุ | `Notes`, `หมายเหตุ` |

- ในช่องเดียวใส่ได้หลายเบอร์หรือหลายอีเมล โดยคั่นด้วย `,` `;` `/` หรือ `:::` (แบบที่ Google ใช้)
- เบอร์ต่อภายใน เช่น `02-123-4567 ต่อ 12` หรือ `ext 12` จะแปลงเป็น `02-123-4567,12`
  เวลาโทร โทรศัพท์จะรอสายติดแล้วกดเบอร์ต่อให้เอง
- เลขไทย (๐-๙) ในเบอร์โทรและวันเกิดจะแปลงเป็นเลขอารบิก
- เบอร์รูปแบบสากล เช่น `(+66) 81-234-5678` หรือ `+44 (0)20 7946 0000` จะจัดให้โทรออกได้ถูกต้อง
  (`+66 81-234-5678`, `+44 20 7946 0000`)
- คอลัมน์ที่โปรแกรมไม่รู้จักจะถูกข้าม และแจ้งชื่อคอลัมน์ให้ทราบ

> **เคล็ดลับสำหรับ Excel:** ก่อนส่งออก ให้ตั้งรูปแบบคอลัมน์เบอร์โทรเป็น *ข้อความ* (Text)
> ไม่เช่นนั้น Excel จะตัดเลข 0 ข้างหน้าทิ้ง หรือแปลงเป็นเลขแบบวิทยาศาสตร์ (เช่น `8.12E+08`)
> ซึ่งโปรแกรมจะข้ามเบอร์นั้นพร้อมแจ้งเตือน ถ้าใส่ไฟล์ `.xlsx`/`.xls` มาโดยตรง โปรแกรมจะแจ้งให้บันทึกเป็น
> "CSV UTF-8" ก่อน

## ความปลอดภัย

- **กันการแทรกคำสั่งลงในไฟล์ vCard (vCard injection):** อักขระ `\` `,` `;` และการขึ้นบรรทัดใหม่ทุกแบบ
  (CR, LF, U+2028, …) จะถูกแปลงเป็นรหัสหลีก (escape) ตามมาตรฐาน RFC 2426/6350
  ข้อมูลในเซลล์จึงสร้างรายการใหม่ในไฟล์ (เช่น `END:VCARD`) ไม่ได้ และชนิดเบอร์ (`TYPE=`)
  มาจากรายการค่าที่อนุญาตไว้ล่วงหน้าเท่านั้น
- ลบอักขระควบคุม และอักขระกลับทิศทางข้อความ (bidi override) ที่ใช้ปลอมชื่อผู้ติดต่อได้
- ลิงก์เว็บรับเฉพาะ `http`/`https` (ไม่รับ `javascript:`, `data:`, `file:` …) ต้องมีชื่อโดเมน และไม่รับลิงก์ที่มี
  ชื่อผู้ใช้หรือรหัสผ่านอยู่ในลิงก์ เช่น `https://www.bank.co.th@evil.example` ที่ดูเหมือนลิงก์ธนาคาร
  แต่พาไปเว็บอื่น นอกจากนี้ยังตรวจรูปแบบอีเมลกับเบอร์โทรด้วย
- อีเมลและลิงก์ที่มีอักขระล่องหน (เช่น zero-width space) จะถูกปฏิเสธ เพราะทำให้ที่อยู่ปลอม
  ดูเหมือนของจริงได้ เช่น `admin@bank.co.th` ที่มีอักขระล่องหนแทรกอยู่
- รูปแบบค้นหาข้อความ (regex) ทุกตัว และเวลาประมวลผลทั้งไฟล์ เพิ่มตามขนาดข้อมูลแบบเส้นตรง ไฟล์ที่จงใจสร้าง
  (เช่น หัวตารางหลายแสนคอลัมน์) จึงทำให้โปรแกรมค้างไม่ได้ (ไม่มีช่องโหว่ ReDoS หรือ DoS)
  และมีการจำกัดขนาดไฟล์กับขนาดเซลล์
- ข้อความเตือนและข้อความผิดพลาดที่ยกค่ามาจากไฟล์หรือจากคำสั่ง จะถูกแปลงอักขระพิเศษก่อนแสดง
  จึงใช้รหัสควบคุม (ANSI escape) สั่งการหน้าจอเทอร์มินัลไม่ได้
- เขียนผลลัพธ์ลงไฟล์ชั่วคราวก่อน แล้วค่อยเปลี่ยนชื่อไฟล์แทนที่ในขั้นตอนเดียว ถ้าเกิดข้อผิดพลาด
  จึงไม่มีไฟล์ที่เขียนค้างครึ่งเดียว ไฟล์ผลลัพธ์ตั้งสิทธิ์ `600` ให้เจ้าของอ่านได้คนเดียว เพราะเป็นข้อมูลส่วนบุคคล
- ไม่เขียนทับไฟล์ที่มีอยู่แล้วถ้าไม่ใส่ `--force` และไม่เขียนทับไฟล์ CSV ต้นฉบับเด็ดขาด
  รวมถึงกรณีที่ชี้ไปยังไฟล์นั้นผ่านลิงก์สัญลักษณ์ (symlink)
- ไม่เขียนทับไฟล์พิเศษ เช่น อุปกรณ์ (`/dev/null`) หรือ FIFO แม้ใส่ `--force` ถ้าต้องการส่งออกทาง
  เอาต์พุตมาตรฐาน ให้ใช้ `-o -`
- ไฟล์ CSV ที่เครื่องหมายคำพูดไม่ปิดจะแจ้งข้อผิดพลาด แทนที่จะรวมหลายแถวเป็นรายชื่อเดียวแบบเงียบ ๆ

### ความปลอดภัยของเว็บไซต์

- **หน้าเว็บ:** ใส่ข้อความจากไฟล์ลงหน้าเว็บด้วย `textContent` เท่านั้น และตั้ง Content-Security-Policy ห้ามสคริปต์แทรก
  (inline) ชื่อผู้ติดต่อที่มีโค้ด HTML จึงรันไม่ได้ (กัน XSS) และห้ามเว็บอื่นฝังหน้านี้ไว้ในกรอบ (กัน clickjacking)
- **API แปลงไฟล์:** ต้องมี header `X-Requested-With: csv2vcf` ซึ่งเว็บอื่นส่งข้ามโดเมนไม่ได้ (กัน CSRF)
- **เปิดได้เฉพาะไฟล์ในรายการ:** มีแค่หน้าเว็บ สคริปต์ สไตล์ และไฟล์ตัวอย่าง จึงไต่ไดเรกทอรีไปอ่านไฟล์อื่นไม่ได้
- **จำกัดทรัพยากร:**
  - ขนาดไฟล์และจำนวนพารามิเตอร์
  - จำนวนไฟล์ที่รับและแปลงพร้อมกัน
  - จำนวนการเชื่อมต่อพร้อมกัน
  - เวลารวมในการรับคำขอ ซึ่งกัน client ที่ส่งทีละไบต์ช้า ๆ (slowloris)
- **ผลลัพธ์ใหญ่:** ส่งกลับทีละช่วง ผู้ใช้เน็ตช้ายังดาวน์โหลดได้ครบ
- **ข้อความผิดพลาด:** ไม่ส่งรายละเอียดภายในให้ผู้ใช้ หน้า error เป็นข้อความธรรมดา header `Server` ไม่บอกรุ่นของ Python
  และ log escape อักขระควบคุม
- **`Content-Length`:** รับเฉพาะตัวเลขล้วน (ไม่รับ `2_4`, `+24` หรือตัวเลขภาษาอื่น) เพื่อให้ตีความตรงกับ proxy เสมอ
- **encoding ที่เลือกได้:** มีเฉพาะที่อยู่ในรายการ เพราะ codec บางตัวถอดรหัสข้อมูลที่จงใจสร้างได้ช้ามาก
